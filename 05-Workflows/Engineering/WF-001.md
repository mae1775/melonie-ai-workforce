# WF-001: Secure Task Intake
**Status:** design, not implemented.  **Trigger:** Authenticated manual/webhook.

## Contract
- Input: Owner request payload.
- Output: tasks.created.
- Required envelope: `event_id`, `workspace_id`, `project_id?`, `task_id?`, `correlation_id`, `occurred_at`, `schema_version`.
- Authorization: workflow identity + workspace ACL; explicit approval for side effects.

## Proposed n8n node sequence
1. Trigger node (Authenticated manual/webhook); receive event, capture immutable request ID.
2. Code/Set node: normalize envelope and validate schema; stop with structured error on failure.
3. Storage read: load workspace/project configuration, current policy and task state.
4. IF node: global pause, role authorization, cost and concurrency checks; deny by default.
5. Execute Sub-workflow: reusable deterministic handler or DeepSeek runner, as appropriate; use bounded timeouts.
6. Code node: validate handler output and enforce output schema; never execute model-proposed tools directly.
7. Storage write: append audit event, persist state transition, artifacts and cost ledger.
8. Notification node: send approved internal status update or create approval request if needed.
9. Error workflow: classify transient vs permanent failure; persist incident, reconcile unknown outcomes.

## Workflow-specific rules
- Create task once using client_request_id; never call model before validation.
- Failure cases: Reject missing workspace/project, bad signature, invalid task fields.
- Do not modify existing client acquisition or job application workflows during design or initial import.

## Required test fixtures
- Happy path with one authorized workspace/project.
- Invalid or missing identity and cross-project context.
- DeepSeek 429/timeout or malformed output when applicable.
- Duplicate event and retry after partial completion.
- Global pause and exhausted budget.
- For any external side effect: approval mismatch and unknown-outcome reconciliation.

## Observability
Emit `workflow_started`, `workflow_blocked`, `workflow_succeeded`, `workflow_failed` with IDs, sanitized payload hashes, elapsed time, model token usage if relevant, and error category. No raw secrets or confidential source content in logs.
